    Model-View-Controller (MVC) Architectural Specification

    Detailed component analysis and architectural responsibilities for the IT Service Request System.

    Design Pattern
    Model
    ServiceRequest.java

    • Business Entity: Represents the IT Service ticket.
    • Encapsulation: Private fields for employeeId, employeeName, department, problemCategory, problemDescription, priority, and requestId.
    • JavaBean Compliance: Public default constructor, parameterized constructor, getters & setters, Serializable.
    • Purity: Completely free of HTML markup and HTTP request/response objects.

    View
    serviceRequest.jsp & acknowledgement.jsp

    • User Presentation: Generates HTML interface for client browsers.
    • Form View (serviceRequest.jsp): Provides form controls for data entry and displays validation alerts.
    • Result View (acknowledgement.jsp): Reads Model attributes from Request Scope and renders the formatted confirmation ticket.
    • Passive Role: Never performs business validation or database operations.

    Controller
    ServiceRequestServlet.java

    • Central Coordinator: Handles HTTP POST requests via doPost().
    • Parameter Extraction: Reads values using request.getParameter().
    • Server-Side Validation: Checks mandatory fields, allowed categories, and valid priority options.
    • Model Creation: Generates SR-1001 ID and instantiates ServiceRequest.
    • Navigation & Forwarding: Attaches Model to Request Scope and forwards via RequestDispatcher.

    Step-by-Step Request Execution Pipeline

    1

    Client Interaction on JSP View

    Employee enters details into serviceRequest.jsp and clicks Submit. The browser packages inputs and transmits an HTTP POST request to /ServiceRequestServlet.

    2

    Servlet Interception & Local Scope Initialization

    The servlet container invokes ServiceRequestServlet.doPost() on a dedicated thread. Parameters are extracted into method-local variables to ensure thread-safety.

    3

    Server-Side Validation Gate

    The controller evaluates mandatory fields (non-empty ID, name length, valid category enum, minimum 10 char description). If invalid, it repopulates previous values and forwards back to serviceRequest.jsp with error alerts.

    4

    Model Instantiation & Unique ID Generation

    Upon valid input, the controller generates a sequential identifier (`SR-1001` via `AtomicInteger`) and creates a new ServiceRequest JavaBean instance.

    5

    Request Attribute Binding & Server-Side Forwarding

    Controller executes request.setAttribute("serviceRequest", serviceRequest) and dispatches the request to acknowledgement.jsp via RequestDispatcher.forward() without URL redirection.

    6

    Acknowledgement View Rendering

    acknowledgement.jsp retrieves the Model from request scope, formats the ticket details with SLA calculations, and delivers the confirmation response to the employee.

    Question 2: Develop the Model - Java Class (5 Marks)

    ServiceRequest.java • Pure JavaBean POJO with encapsulation, constructors & getters/setters

    5 Marks
    src/com/itservice/model/ServiceRequest.java 
    package com.itservice.model;

import java.io.Serializable;

public class ServiceRequest implements Serializable {
    private static final long serialVersionUID = 1L;

    private String employeeId;
    private String employeeName;
    private String department;
    private String problemCategory;
    private String problemDescription;
    private String priority;
    private String requestId;

    // Default No-Arg Constructor (JavaBean compliance)
    public ServiceRequest() {}

    // Parameterized Constructor
    public ServiceRequest(String requestId, String employeeId, String employeeName,
                          String department, String problemCategory,
                          String problemDescription, String priority) {
        this.requestId = requestId;
        this.employeeId = employeeId;
        this.employeeName = employeeName;
        this.department = department;
        this.problemCategory = problemCategory;
        this.problemDescription = problemDescription;
        this.priority = priority;
    }

    // Getters and Setters
    public String getEmployeeId() { return employeeId; }
    public void setEmployeeId(String employeeId) { this.employeeId = employeeId; }

    public String getEmployeeName() { return employeeName; }
    public void setEmployeeName(String employeeName) { this.employeeName = employeeName; }

    public String getDepartment() { return department; }
    public void setDepartment(String department) { this.department = department; }

    public String getProblemCategory() { return problemCategory; }
    public void setProblemCategory(String problemCategory) { this.problemCategory = problemCategory; }

    public String getProblemDescription() { return problemDescription; }
    public void setProblemDescription(String problemDescription) { this.problemDescription = problemDescription; }

    public String getPriority() { return priority; }
    public void setPriority(String priority) { this.priority = priority; }

    public String getRequestId() { return requestId; }
    public void setRequestId(String requestId) { this.requestId = requestId; }
}

    Question 3: Develop the Controller Servlet (10 Marks)

    ServiceRequestServlet.java • doPost(), parameter extraction, validation, Model creation & forwarding

    10 Marks
    src/com/itservice/controller/ServiceRequestServlet.java 
    @WebServlet(name = "ServiceRequestServlet", urlPatterns = {"/ServiceRequestServlet"})
public class ServiceRequestServlet extends HttpServlet {
    private static final AtomicInteger requestCounter = new AtomicInteger(1000);

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        
        // Q3.b: Read parameters into thread-safe local variables (Q3.h)
        String employeeId = request.getParameter("employeeId");
        String employeeName = request.getParameter("employeeName");
        String department = request.getParameter("department");
        String problemCategory = request.getParameter("problemCategory");
        String problemDescription = request.getParameter("problemDescription");
        String priority = request.getParameter("priority");

        // Q3.c: Server-side validation
        List<String> errors = new ArrayList<>();
        if (employeeId == null || employeeId.trim().isEmpty()) errors.add("Employee ID is required.");
        if (employeeName == null || employeeName.trim().isEmpty()) errors.add("Employee Name is required.");
        if (department == null || department.trim().isEmpty()) errors.add("Department is required.");
        if (problemCategory == null || problemCategory.trim().isEmpty()) errors.add("Category is required.");
        if (problemDescription == null || problemDescription.trim().length() < 10) errors.add("Description must be >= 10 chars.");
        if (priority == null || priority.trim().isEmpty()) errors.add("Priority is required.");

        if (!errors.isEmpty()) {
            request.setAttribute("errors", errors);
            request.getRequestDispatcher("serviceRequest.jsp").forward(request, response);
            return;
        }

        // Q3.e: Generate Request Number
        String requestId = "SR-" + requestCounter.incrementAndGet();

        // Q3.d: Create Model object
        ServiceRequest serviceRequest = new ServiceRequest(
            requestId, employeeId, employeeName, department, problemCategory, problemDescription, priority
        );

        // Q3.f: Set request attributes
        request.setAttribute("serviceRequest", serviceRequest);
        request.setAttribute("requestId", requestId);

        // Q3.g: Forward to acknowledgement.jsp
        RequestDispatcher dispatcher = request.getRequestDispatcher("acknowledgement.jsp");
        dispatcher.forward(request, response);
    }
}

    Viva Voce & Technical Interview Questions

    Key theoretical concepts for Unit IV assessment.

    25+ Questions Available
    Q1

    Why is the MVC pattern preferred over direct JSP-to-database access?

    Direct JSP access (Model 1) results in spaghetti code with business and database logic mixed into presentation markup. MVC (Model 2) achieves clear separation of concerns, higher maintainability, testability, and code reusability across multiple frontends.

    Q2

    What is the difference between RequestDispatcher.forward() and HttpServletResponse.sendRedirect()?

    forward() happens entirely on the server within a single HTTP request, preserving request-scoped attributes without altering the browser URL. sendRedirect() issues an HTTP 302 response instructing the browser to initiate a brand-new HTTP GET request, discarding request attributes and changing the browser URL.

    Q3

    How is thread safety achieved in Java Servlets?

    Because a single Servlet instance is shared across all concurrent client threads in the servlet container, all request-specific data must be stored in method-local variables inside doPost() or doGet(). Method variables reside on each thread's separate stack frame, preventing race conditions.

    Q4

    What is the purpose of the web.xml deployment descriptor?

    web.xml declares servlet configurations, URL mapping patterns (e.g. mapping /ServiceRequestServlet to com.itservice.controller.ServiceRequestServlet), session timeouts, error pages, and welcome file lists for the servlet container.

    Q5

    Why is server-side validation mandatory even when HTML5 validation exists?

    Client-side HTML5 validation can be easily bypassed by disabling JavaScript or sending direct HTTP requests using tools like Postman, curl, or automated scripts. Server-side validation in the Controller Servlet acts as the non-negotiable security gate.
