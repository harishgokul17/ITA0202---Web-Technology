Intrinsic handlers vs. addEventListener()

onclick="..." (intrinsic, in HTML)

  • Handler is written as an attribute on the tag itself, e.g. <button onclick="run()">.
  • Mixes JavaScript into markup — harder to keep structure and behavior separate.
  • An element can hold only one intrinsic handler per event; assigning a new one overwrites the old.
  • No access to options like capture, once, or passive.
  • Quick to demo, but blocked by strict Content-Security-Policy rules in production apps.

element.addEventListener() (modern)

  • Handler is attached in JavaScript: btn.addEventListener('click', run) — markup stays clean.
  • An element can have multiple listeners for the same event, all firing independently.
  • Supports removeEventListener(), plus options like { once: true } or { capture: true }.
  • Works with any event type, including custom events dispatched by your own code.
  • The standard approach in real-world, maintainable front-end code.
